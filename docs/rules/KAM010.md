# KAM010: the prerequisite shares no field with the action it admits: another key's grant admits

A prerequisite (`formerly within W Grant::kind{ }`) whose pattern pins no field of the request
is satisfied by a grant for anyone: Grant for one user and resource admits Access for another.
lint finds it with the representative key (two values of the request's key: the request's and
one other); the trace grants key 2 and ends at Access permitted for key 1, which the
Prerequisite ledger's Sound forbids. Pin the key: `{ input.user: context.input.user }`.

Level: **error** (`kamanu lint` exits 1). It needs lint's ledger machine (kamanu.fast.ledger), so it is reported for a policy inside step 4's machine that is a ledger policy.

## Example

On any engine (here the reference one):

```dogwood
@id("access_after_grant")
permit (principal, action == Drupe::Action::"Access", resource)
when temporal {
    formerly within 24h Drupe::Action::"Grant"::response{ }
};
```

lint's finding (line 4, column 47): KAM010 the prerequisite shares no field with the action it admits: Grant::response pins no field of the request, so Grant for one key admits Access for another. Pin the key, e.g. { input.user: context.input.user }.

The trace:

1. a caller a rule admits asks Access | ledger: revoked for the request's key
2. a caller a rule admits asks Grant for another key | ledger: revoked for the request's key
3. the engine decides Grant for another key: permitted | ledger: revoked for the request's key
4. Grant for another key completes and its effect lands | ledger: revoked for the request's key
5. the engine decides Access: permitted | ledger: revoked for the request's key

Note: found with the representative key: two values of the request's key, the request's and another.

## Suppressing it

`// kamanu-ignore KAM010: <reason>` at the end of the pattern's line or alone on the line above it;
the reason is required, and the finding stays in the output and the SARIF.
