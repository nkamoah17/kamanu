# T5: what each premise query can say

`statuses.json` lists, for each of the six premise queries, the statuses `kamanu.evidence.premises.map`
can give its premise, why, and the constructs it may establish, each with the assumptions it needs.

No query produces `observed`. A static query runs nothing; a fact is `observed` when a caller who holds
the record of a run or a live probe puts its path in the fact's `record`.

What `established` does not mean. It is the pattern plus a claim about library objects, under the written
assumptions. The graph shows no rebinding, patching or shadowing of the names involved; it cannot show
`setattr`, `globals()`, `exec` or an environment that replaces a module, which is what the first assumption
of most constructs is about. The assumptions are not checked by anything here.

The fixtures under `fixtures/premises/` are the two ends for each query: code its pattern matches where the
premise is false when run (`probe.py`), and code of the construct where it holds. `facts.json` there is real
Joern 4.0.676 output, regenerated by running each query on each directory.
`tests/test_premises_constructs.py` (live, JOERN_HOME) holds the look-alikes that must stay patterns.
