# KAM009: one approval, many actions: a credit is spent twice where the engine decides before it records

A credit policy (`count(Sell::request{key}) <= count(Approve::response{key})`: one approval, one
sale) is judged on the Credit ledger: credited is the approvals that landed, used the sales
admitted, running or landed. On an engine that decides a request before it records it, two
sales can both be decided on a history that holds one approval and neither sale: both are
admitted, and one approval pays for two sales. Sound fails at R0 with a credit landed.

The fix is in the engine (record what it admits in the step that admits it) or in the rule (a
credit that must not be shared needs the engine's atomicity); there is no one-token edit.

Level: **error** (`kamanu lint` exits 1). It needs lint's product machine (kamanu.fast.credit), so it is reported for a policy inside step 3's machine.

## Example

On a not-atomic engine (it decides, then records):

```dogwood
@id("one_approval_one_sale")
permit (principal, action == Drupe::Action::"Sell", resource)
when temporal {
    (count for (t: Timepoint). where (
        formerly within 24h (Drupe::Action::"Sell"::request{ input.user: context.input.user } && tp(t))
    ))
    <= count for (t: Timepoint). where (
        formerly within 24h (Drupe::Action::"Approve"::response{ input.user: context.input.user } && tp(t))
    )
};
```

lint's finding (line 5, column 51): KAM009 one Approve, many Sell: on a not-atomic engine (it decides, then records) a Sell is admitted while the Approve it spends is already spent: 2 Sell on 1 Approve (Sound FAILS at R0). The second decision reads a history the first has not reached yet.

The trace:

1. a caller a rule admits asks Sell | ledger: credited 0, used 0, doubt 0
2. a caller a rule admits asks Approve | ledger: credited 0, used 0, doubt 0
3. the engine decides Approve: permitted | ledger: credited 0, used 0, doubt 0
4. the engine records Approve's request | ledger: credited 0, used 0, doubt 0
5. Approve completes and its effect lands | ledger: credited 1, used 0, doubt 0
6. a caller a rule admits asks Sell | ledger: credited 1, used 0, doubt 0
7. the engine decides Sell: permitted | ledger: credited 1, used 1, doubt 0
8. the engine decides Sell: permitted | ledger: credited 1, used 2, doubt 0

Note: one Approve, two Sell: the engine must record each admitted Sell before it decides the next (an atomic engine), or the rule must read what has completed.
