# KAM008: a late reset on a stale view: the revoking call completed, yet a view one event behind permits

A latch (`!Revoke since Grant`) is read on an engine whose guard may read a view one event
behind the history (Lag 1). The revoking call completes, its response is the newest event, and
the next decision of the guarded action reads the view without it: the latch still stands, so
the action is permitted although the ledger says revoked. Your revoke does not revoke.

lint reports it at the reset pattern's line where the Latch ledger's Sound fails on that profile
through a permit decided on the stale view after a reset. The fix is in the engine (read your own
writes: Lag 0) or in the rule (a revoke that must hold before the next decision is not a
history pattern); there is no one-token edit.

Level: **error** (`kamanu lint` exits 1). It needs lint's ledger machine (kamanu.fast.ledger), so it is reported for a policy inside step 4's machine that is a ledger policy.

## Example

On an engine whose view lags one event (Lag 1):

```dogwood
@id("access_while_granted")
permit (principal, action == Drupe::Action::"Access", resource)
when temporal {
    !Drupe::Action::"Revoke"::response{ input.user: context.input.user, input.resource: context.input.resource }
    since within 24h
    Drupe::Action::"Grant"::response{ input.user: context.input.user, input.resource: context.input.resource }
};
```

lint's finding (line 4, column 29): KAM008 a late reset on a stale view: on an engine whose view lags one event (Lag 1) the guard reads a view one event behind, so Access is permitted after Revoke completed and revoked it: your revoke does not revoke.

The trace:

1. a caller a rule admits asks Access | ledger: revoked for the request's key
2. a caller a rule admits asks Grant | ledger: revoked for the request's key
3. the engine decides Grant: permitted | ledger: revoked for the request's key
4. Grant completes and its effect lands | ledger: granted for the request's key
5. a caller a rule admits asks Revoke | ledger: granted for the request's key
6. the engine decides Revoke: permitted | ledger: granted for the request's key, 1 revoking call(s) in flight
7. Revoke completes and its effect lands | ledger: revoked for the request's key
8. the engine decides Access: permitted | ledger: revoked for the request's key

Note: the trace ends at the permit decided on the stale view, while the ledger says revoked.

## Suppressing it

`// kamanu-ignore KAM008: <reason>` at the end of the pattern's line or alone on the line above it;
the reason is required, and the finding stays in the output and the SARIF.
