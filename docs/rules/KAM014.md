# KAM014: a refused action burns the credit: a refused request is counted as a debit

A credit policy whose debits are read from the guarded action's requests counts a refused
request too, on an engine that keeps the requests it refuses: a sale asked before its approval
landed is refused, stays in the history, and spends the approval that lands later, so the sale
that approval was for is refused. Tight fails at R0 after an earlier refusal of the action.

Read the debit from what ran (the action's responses, with `<` for the current call) or keep
refusals out of the history.

Level: **error** (`kamanu lint` exits 1). It needs lint's product machine (kamanu.fast.credit), so it is reported for a policy inside step 3's machine.

## Example

On an engine whose refusals leave a request in the history:

```dogwood
@id("one_approval_one_sale")
permit (principal, action == Drupe::Action::"Sell", resource)
when temporal {
    (count for (t: Timepoint). where (
        formerly within 24h (Drupe::Action::"Sell"::request{ input.user: context.input.user } && tp(t))
    ))
    <= count for (t: Timepoint). where (
        formerly within 24h (Drupe::Action::"Approve"::response{ input.user: context.input.user } && tp(t))
    )
};
```

lint's finding (line 5, column 51): KAM014 a refused Sell burns the Approve: on an engine whose refusals leave a request in the history a refused Sell request stays in the history and is counted as a debit, so the Approve that nothing used is spent and the next Sell is refused (Tight FAILS at R0).

The trace:

1. a caller a rule admits asks Sell | ledger: credited 0, used 0, doubt 0
2. a caller a rule admits asks Sell | ledger: credited 0, used 0, doubt 0
3. the engine decides Sell: refused | ledger: credited 0, used 0, doubt 0
4. a caller a rule admits asks Approve | ledger: credited 0, used 0, doubt 0
5. the engine decides Approve: permitted | ledger: credited 0, used 0, doubt 0
6. Approve completes and its effect lands | ledger: credited 1, used 0, doubt 0
7. the engine decides Sell: refused | ledger: credited 1, used 0, doubt 0

Note: read the debit from what ran: Sell::request counts the refused requests too.
